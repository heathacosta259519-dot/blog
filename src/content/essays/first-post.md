笔记软件里已经堆了几百篇东西：Python 的章节速查、Go 的读书笔记、C# 的语法碎片，还有一堆写了一半就停下的实验记录。它们都在，但只有我一个人能看到，而且三个月后我自己也找不到。

所以有了这个站。它的定位很窄：

- **学习成果** —— 把啃过的东西整理成能给别人看的形状。能不能讲明白，是检验有没有真懂的最低成本方式。
- **日常琐事** —— 短一点，随手写。不追求成篇。
- **dotfiles** —— 配置本身放在仓库里，这里只写**为什么这么配**。配置文件会过时，取舍的理由不会。

## 为什么不用现成的平台

不是排斥平台，是几个具体需求对不上：

| 需求 | 现成平台 | 自建静态站 |
| :--- | :--- | :--- |
| 用 Obsidian 直接写 | 要复制粘贴 | 直接读 Markdown |
| 代码高亮、表格、脚注 | 看运气 | 构建时生成 |
| 数据在自己手里 | 不一定 | 纯文件 |
| 成本 | 免费版有广告/限制 | 0 元 |

代价是得自己维护。但这个代价我付得起：内容全是 Markdown，站点是纯静态产物，最坏情况下把仓库 clone 下来 `pnpm build` 就能原地复活。

## 技术选择

三件事定下来就没再纠结：

1. **Astro** 做静态生成。博客本质是"一堆文档 + 一个列表页"，Astro 的内容集合（content collections）正好干这个，输出的还是纯 HTML，不绑平台。
2. **GitHub Pages** 托管。项目页挂在 `/<repo>/` 子路径下，够用，而且零成本。
3. **发布闸门**。Obsidian 库里混着 PDF、密钥、内网地址，所以公开内容走白名单：笔记 frontmatter 写 `publish: true` 才会被同步出来，同步时还会扫一遍高危字符串。默认私有，要公开得主动声明。

第 3 条是整套东西里唯一需要认真设计的地方。写博客不难，难的是**别把不该出门的东西带出去**。

## 接下来

先把 Python 那套速查笔记搬过来，再补 Go 的。写作节奏不设 KPI —— 有值得写的东西才写，硬凑出来的更新对谁都没好处。
